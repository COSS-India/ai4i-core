# Pay-Per-Use (PPU) — Local Setup

Companion to [`SETUP_GUIDE.md`](SETUP_GUIDE.md). The core setup **does not** bill anything: inference works, but no budget is deducted and no quota is counted. Use this document when you want Pay-Per-Use (tiers, budgets, quotas and per-request billing) working locally.

**Before you start:** complete `SETUP_GUIDE.md` Steps 1–9 with the **full stack (Step 4, Option B)**. Kafka is required. auth-service (`:8081`), platform-core-service (`:8095`), inference-service (`:8090`) and the Simple UI (`:3000`) must all be running, and at least one model service must have a working endpoint (Step 10).

**OS:** Linux / WSL2 only (same as the main guide).

---

## How billing works

```
client ─► auth-service /auth/validate ─► inference-service ─► OTel span "ai-inference"
          (budget / quota / tier checks)                              │
                                                                      ▼  Kafka: kafka-topic-otel-trace
auth-service ◄── /internal/ppu/* (exhausted flags) ◄── payperuse_consumer ──► ai4iplatform_core
                                                       (prices the span)      budget_usage, quota_usage
```

| Piece | Role |
|---|---|
| **auth-service** | Owns tenants, applications and API keys, and their budgets. Rejects a request at `/auth/validate` when the key's budget or the tenant's quota is exhausted (from flags in Redis). |
| **platform-core-service** | Owns tiers (`tiers`, `tier_quotas`), the task-type catalogue (`inference_types`), and service pricing (`mm_services.cost_per_unit`, `unit_size`, `tier_ids`). |
| **inference-service** | Runs the model and emits an `ai-inference` span to Kafka carrying `tenantId`, `api_key_id`, `tier_id`, `service_id` and token counts. |
| **kafka-consumers / `payperuse_consumer`** | Reads those spans, computes the cost, debits `budget_usage` and counts `quota_usage`, and tells auth-service when a budget or quota runs out. |

Only **API-key** requests are billed. Requests made with a logged-in user's session (JWT) are skipped.

## Step 1: Check the service settings

These must be set in the service `.env` files generated by `setup-env.sh`. Restart a service after changing its `.env`; `--reload` does not pick up `.env` changes.

| File | Variable | Required value | Why |
|---|---|---|---|
| `services/inference-service/.env` | `KAFKA_ENABLED` | `true` | **Defaults to `false`.** Without it no spans reach Kafka and nothing is billed. Traces need the same setting; see [`TRACING-OBSERVABILITY-LOCAL-SETUP.md`](TRACING-OBSERVABILITY-LOCAL-SETUP.md). If you've already set it up for tracing, nothing more to do here. |
| `services/inference-service/.env` | `KAFKA_TOPIC_OTEL_TRACE` | `kafka-topic-otel-trace` | Topic the consumer reads |
| `services/auth-service/.env` | `PLATFORM_CORE_DB_NAME` (+ `_USER`, `_PASSWORD`, `_HOST`, `_PORT`) | `ai4iplatform_core`, plus the Postgres credentials | Tier assignment and API-key budget snapshots write to the platform-core database |
| `services/platform-core-service/.env` | `AUTH_DB_NAME` | `ai4iplatform_auth` | Usage endpoints and tier-status pushes |
| `services/platform-core-service/.env` | `AUTH_SERVICE_URL` | `http://localhost:8081` | Tier activate/deactivate notifies auth-service |

All three services and the consumer must use the **same Redis host and `REDIS_DB`**, because they share cache keys.

## Step 2: Run the PPU consumer

`services/kafka-consumers` is a separate service that `SETUP_GUIDE.md` does not start. Without it, inference works but nothing is ever billed.

### 2.1 Install

```bash
cd services/kafka-consumers
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2.2 Create its `.env`

The consumer reads `.env` from the **directory you start it in**, which is `services/kafka-consumers/`. `setup-env.sh` writes a `.env` into `consumers/payperuse_consumer/` instead, where it isn't read. Its template also has the wrong Postgres credentials (`admin` / `root`) and no PII key.

From the repo root, create the right file:

```bash
cd "<path-to>/ai4i-core"   # repo root

cp services/kafka-consumers/consumers/payperuse_consumer/env.template services/kafka-consumers/.env

ENVF=services/kafka-consumers/.env
get() { grep -m1 "^$1=" "$2" | cut -d= -f2-; }

sed -i "s|^POSTGRES_USER=.*|POSTGRES_USER=$(get POSTGRES_USER .env)|"                     $ENVF
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(get POSTGRES_PASSWORD .env)|"         $ENVF
sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$(get REDIS_PASSWORD .env)|"                  $ENVF
sed -i "s|^PII_ENCRYPTION_KEY=.*|PII_ENCRYPTION_KEY=$(get PII_ENCRYPTION_KEY services/auth-service/.env)|" $ENVF
```

Then check it:

```bash
grep -E '^(KAFKA_SERVER|TOPIC_PAY_PER_USE|AUTH_SERVICE_URL|POSTGRES_USER|POSTGRES_HOST|PLATFORM_CORE_DB|AUTH_SERVICE_DB|REDIS_HOST)=' services/kafka-consumers/.env
```

| Variable | Expected |
|---|---|
| `KAFKA_SERVER` | `localhost:9093` |
| `TOPIC_PAY_PER_USE` | `kafka-topic-otel-trace` |
| `AUTH_SERVICE_URL` | `http://localhost:8081` |
| `POSTGRES_USER` / `POSTGRES_HOST` | Same as the root `.env` / `localhost` |
| `PLATFORM_CORE_DB` / `AUTH_SERVICE_DB` | `ai4iplatform_core` / `ai4iplatform_auth` |
| `PII_ENCRYPTION_KEY` | Identical to auth-service's. Only matters for PPU notification emails. |

### 2.3 Seed the consumer's Kafka offsets (first run only)

The consumer uses group `aio-python-consumers` with `KAFKA_AUTO_OFFSET_RESET=error`. On a fresh Kafka that group has no saved position, so the consumer logs `No valid committed offset … Seed the group's offsets deliberately` and processes nothing. This is a deliberate guard against re-billing old spans.

Start the group at the **end** of the topic, so only new requests are billed. The consumer must not be running yet:

```bash
docker exec ai4v-kafka kafka-consumer-groups --bootstrap-server kafka:29092 \
  --group aio-python-consumers --topic kafka-topic-otel-trace \
  --reset-offsets --to-latest --execute
```

Do **not** switch `KAFKA_AUTO_OFFSET_RESET` to `earliest`. That replays every span still in the topic and bills it.

### 2.4 Start it

```bash
cd services/kafka-consumers
source .venv/bin/activate
python main.py --consumer payperuse_consumer
```

It's running when the log shows `Consumer started | group_id=aio-python-consumers topic=kafka-topic-otel-trace …`. Leave it running in its own terminal.

## Step 3: Configure PPU data

No tiers are seeded; you create them. Do these steps in order, logged in to the Simple UI (http://localhost:3000) as `admin@ai4inclusion.org`. The PPU permissions (140–147) are granted to the **ADMIN** role only.

| # | What | Where (UI) | API (for reference) |
|---|---|---|---|
| 1 | **Create a tier** with a monthly quota per task type (e.g. `nmt` = 1000). It is created **INACTIVE**. | `/tier-management` | `POST /api/v1/pay-per-use/tier` — `{name, description, quotas:[{modelTaskType, limit}]}` |
| 2 | **Activate the tier** | `/tier-management` | `PATCH /api/v1/pay-per-use/tier/{tier_id}/status` — `{"status":"ACTIVE"}` |
| 3 | **Price the service and allow it on the tier.** Set cost per unit, unit size, and add the tier to the service's tiers. | Service management | `PATCH /api/v1/services` — `taskType`, `costPerUnit`, `unitSize` and `tierIds` must be sent together |
| 4 | **Assign the tier to the tenant**, and give the tenant a budget | `/institution-management` → Manage tier / budget | `PATCH /api/v1/auth/tenants/{id}/tier` — `{"tier_id":"<uuid>"}`; `PATCH /api/v1/auth/tenants/{id}/budget` — `{"action":"top-up","amount":1000}` |
| 5 | **Create an application** under the tenant and give it a budget | `/institution-management` / `/api-key-management` | `POST /api/v1/auth/tenants/{tenant_id}/applications` |
| 6 | **Create an API key** for that application with a budget (fixed amount or % of the application's budget) and the task's inference permission (e.g. `nmt.inference`) | `/api-key-management` | `POST /api/v1/auth/api-keys` — `{key_name, permissions, application_id, budget}` or `allocated_percentage` |

**Notes**
- **Order matters.** Creating an API key fails with `NO_ACTIVE_TIER` if the tenant has no active tier, and with `APPLICATION_BUDGET_NOT_SET` if the application has no budget.
- `modelTaskType` must be a seeded inference type: `llm`, `asr`, `nmt`, `tts`, `ner`, `ocr`, `transliteration`, `language-detection`, `language-diarization`, `speaker-diarization`, `audio-lang-detection`, `pipeline`.
- Editing an **existing** tier's quota does not apply immediately. It is stored as a pending quota.
- auth-service caches tier status for up to 10 minutes (`tier_status_cache`). A tier you just deactivated may still be accepted for a while.
- **Copy the API key when it's shown.** You need it in Step 4.

## Step 4: Make a billable request

> **Known limitation: billing doesn't work through the Simple UI locally.**
> Locally, the Next.js proxy (`frontend/simple-ui/src/pages/api/v1/[...proxy].ts`) stands in for the production gateway. It forwards only `X-User-ID`, `X-Tenant-ID`, `X-Tenant-Name` and `X-Permission-IDs` from `/auth/validate`. It drops `X-Auth-Type`, `X-API-Key-ID` and `X-Tier-ID`, which billing needs. Requests sent through `localhost:3000` therefore produce spans with no API key or tier, and **the consumer skips them**. The tier gate is skipped too.

To test billing locally, call inference-service **directly** and set those headers yourself, as the gateway would.

**4.1 Look up the IDs**

```bash
# API key id, application id and tenant id (auth DB)
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_auth -c \
  "select k.id as api_key_id, k.key_name, k.application_id, a.tenant_id, k.allocated_budget
     from api_key k join applications a on a.id = k.application_id order by k.id desc limit 5;"

# Tenant's tier (auth DB)
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_auth -c \
  "select id as tenant_id, tier_id, allocated_budget from tenants;"

# A priced service that allows that tier (core DB)
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_core -c \
  "select service_id, task_type, cost_per_unit, unit_size, tier_ids from mm_services where tier_ids is not null;"
```

**4.2 Call inference** (NMT example)

```bash
curl -s http://localhost:8090/api/v1/nmt/inference \
  -H 'Content-Type: application/json' \
  -H 'X-Auth-Type: api_key' \
  -H 'X-Tenant-ID: <tenant_id>' \
  -H 'X-API-Key-ID: <api_key_id>' \
  -H 'X-Application-ID: <application_id>' \
  -H 'X-Tier-ID: <tier_id>' \
  -d '{"serviceId":"<service_id>","input":[{"source":"hello world"}],"config":{"language":{"sourceLanguage":"en","targetLanguage":"hi"}}}'
```

The call must **succeed**. A request that fails at the model endpoint is not billed.

## Step 5: Verify the deduction

**Consumer terminal:** a line for the processed span with no error after it.

**Budget used per API key** (core DB). A row is created when the key is created; `api_key_budget_used` should go up after each call:

```bash
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_core -c \
  "select api_key_id, api_key_budget_snap, api_key_budget_used, updated_at from budget_usage;"
```

**Quota used per tenant, task type and month** (core DB):

```bash
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_core -c \
  "select tenant_id, inference_name, billing_month, monthly_quota_snap, monthly_quota_used from quota_usage;"
```

**Exhausted flags** (Redis). auth-service blocks the key when these are `1`:

```bash
RP=$(grep -m1 '^REDIS_PASSWORD=' .env | cut -d= -f2-)
docker exec ai4v-redis redis-cli -a "$RP" --no-auth-warning --scan --pattern 'auth:apikey:*'
docker exec ai4v-redis redis-cli -a "$RP" --no-auth-warning HGETALL 'auth:apikey:<key from the line above>'
# fields: tier_id, budget-exhausted, quota-<service>
```

**UI:** `/usage-dashboard` shows spend and usage per tenant and application.

**Test exhaustion:** give an API key a very small budget, or set a tier quota of `1`, then repeat Step 4.2. Once the consumer flags it, a request **through the gateway path** (`/auth/validate`) returns `429 BUDGET_EXHAUSTED` or `429 QUOTA_EXCEEDED`. A direct call to `:8090` bypasses `/auth/validate`, so it isn't blocked.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Consumer logs `No valid committed offset … Seed the group's offsets` | Run Step 2.3 (with the consumer stopped), then start it again. |
| Consumer fails on startup with a missing field (`TOPIC_PAY_PER_USE`, `POSTGRES_USER`, …) | It isn't reading your `.env`. Start it from `services/kafka-consumers/`, with `.env` in that folder (Step 2.2). |
| Consumer can't connect to Postgres | `.env` still has the template's `admin` / `root`. Redo Step 2.2. |
| `budget_usage` doesn't change | Check in order: inference `KAFKA_ENABLED=true`; the call went to `:8090` directly with `X-Auth-Type: api_key` and `X-API-Key-ID` (Step 4); the service has a non-zero `cost_per_unit`; the inference call succeeded; the consumer is running. |
| `quota_usage` has no row | `X-Tier-ID` missing from the request, or the tier has no quota for that task type. |
| Creating an API key → `NO_ACTIVE_TIER` | Assign an **active** tier to the tenant first (Step 3, rows 2 and 4). |
| Creating an API key → `APPLICATION_BUDGET_NOT_SET` | Give the application a budget first (Step 3, row 5). |
| Inference → 403 "not available for your quota" | The service's `tier_ids` doesn't include the tenant's tier (Step 3, row 3). |
| Assigning a tier → `TIER_NOT_FOUND` | The tier is still INACTIVE. Activate it (Step 3, row 2). |

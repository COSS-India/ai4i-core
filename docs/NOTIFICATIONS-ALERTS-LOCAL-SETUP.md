# Notifications & Alerts — Local Setup

Companion to [`SETUP_GUIDE.md`](SETUP_GUIDE.md). Use this to get notification **emails** working locally.

**Before you start:**
- Core setup done with the **full stack** (`SETUP_GUIDE.md` Step 4, Option B).
- auth-service, platform-core-service, inference-service and the Simple UI (`:3000`) running.
- SMTP credentials available (e.g. Amazon SES SMTP).
- For PPU notifications (budget/quota threshold and exhausted), also complete [`PPU-LOCAL-SETUP.md`](PPU-LOCAL-SETUP.md).

## How it works

| | |
|---|---|
| Examples | Tier assigned/changed, budget assigned/updated/exhausted, quota threshold/exhausted, error-rate and latency alerts |
| Path | auth-service / platform-core / `payperuse_consumer` → Kafka `notification.events` → **`notifications_consumer`** → email |
| Email settings | `services/kafka-consumers/consumers/notifications_consumer/.env` |
| Manage in UI | `/notifications-alerts` |

## Step 1: Configure email

### Step 1.1: auth-service (onboarding emails: tenant set-password, verify email)

In `services/auth-service/.env`, fill the **existing** lines (don't add new ones), then restart auth-service:

```bash
EMAIL_PROVIDER=smtp
EMAIL_FROM=<verified sender, e.g. noreply@yourdomain.org>
SMTP_HOST=email-smtp.<region>.amazonaws.com     # host only, no :587
SMTP_PORT=587
SMTP_USERNAME=<smtp username>
SMTP_PASSWORD=<smtp password>
SETUP_LINK_BASE_URL=http://localhost:3000/auth/set-password
VERIFY_LINK_BASE_URL=http://localhost:3000/auth/verify-email
```

If `SMTP_HOST` is blank, emails are only printed in the auth-service log (`[ConsoleEmailProvider] would send email`). If `EMAIL_FROM` is blank, the request fails with `EMAIL_FROM is required`.

### Step 1.2: notifications_consumer (tier, budget, quota and monitoring emails)

Edit `services/kafka-consumers/consumers/notifications_consumer/.env`. It's generated by `setup-env.sh` but defaults to **console** (prints emails instead of sending them) and has blank database credentials:

```bash
POSTGRES_USER=<same as root .env>
POSTGRES_PASSWORD=<same as root .env>
REDIS_PASSWORD=<same as root .env>

EMAIL_PROVIDER=smtp
EMAIL_FROM=<verified sender, e.g. noreply@yourdomain.org>
SMTP_HOST=email-smtp.<region>.amazonaws.com     # host only, no :587
SMTP_PORT=587
SMTP_USERNAME=<smtp username>
SMTP_PASSWORD=<smtp password>
```

**Shortcut:** once Step 1.1 works, run this from the repo root. It copies the database and Redis values from the root `.env`, copies SMTP from auth-service, and quotes values that contain spaces:

```bash
F=services/kafka-consumers/consumers/notifications_consumer/.env
A=services/auth-service/.env
get() { grep -m1 "^$1=" "$2" | cut -d= -f2-; }

for k in POSTGRES_USER POSTGRES_PASSWORD REDIS_PASSWORD; do
  sed -i "s|^$k=.*|$k=$(get $k .env)|" $F; done
for k in EMAIL_FROM SMTP_HOST SMTP_PORT SMTP_USERNAME SMTP_PASSWORD; do
  sed -i "s|^$k=.*|$k=$(get $k $A)|" $F; done
sed -i 's|^EMAIL_PROVIDER=.*|EMAIL_PROVIDER=smtp|' $F
sed -i -E 's/^(PLATFORM_NAME|EMAIL_FROM_NAME)=([^"].* .*)$/\1="\2"/' $F

grep -E '^(POSTGRES_USER|EMAIL_PROVIDER|EMAIL_FROM|SMTP_HOST|PLATFORM_NAME)=' $F   # check
```

- `PLATFORM_NAME` must not be blank, or the consumer won't start.
- **Values with spaces must be quoted** (e.g. `PLATFORM_NAME="AI Switch"`), because Step 2.3 loads this file with `source`. Otherwise you'll see `Switch: command not found`.
- A password containing `|` or `&` breaks the `sed` copy; paste that one by hand.
- Re-running `setup-env.sh` resets this file, so redo this step afterwards.

> On SES sandbox, both the sender and every recipient address must be verified in SES.

## Step 2: Run the notifications consumer

### Step 2.1: Install

Skip if already done for PPU.

```bash
cd services/kafka-consumers
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd ../..
```

### Step 2.2: Seed the consumer's Kafka offsets (first run only)

Run this once, from the repo root, so the consumer begins at the latest message instead of exiting on start (`KAFKA_AUTO_OFFSET_RESET=error`). The consumer must not be running yet:

```bash
docker exec ai4v-kafka kafka-consumer-groups --bootstrap-server kafka:29092 \
  --group notification-service --topic notification.events \
  --reset-offsets --to-latest --execute
```

### Step 2.3: Start it

Use a new terminal (one that hasn't loaded an older version of the `.env`). It must run from `services/kafka-consumers`. `payperuse_consumer` uses the `.env` in that folder, so load this consumer's settings explicitly; exported variables take priority over that file:

```bash
cd services/kafka-consumers
source .venv/bin/activate
set -a; source consumers/notifications_consumer/.env; set +a
python main.py --consumer notifications_consumer
```

It's ready when the log shows `Consumer started | group_id=notification-service topic=notification.events`.

## Step 3: Choose who receives what

**Every notification and alert is switched off on a fresh setup.** All recipient roles are `false`, so nothing is emailed until you turn it on.

As admin, open **`/notifications-alerts`** and for each notification or alert you want:
- tick the recipient roles (e.g. `ADMIN`, `TENANT ADMIN`);
- for threshold alerts, set the bands (e.g. 70 / 80 / 90 %).

Institution-scoped items (`TIER_ASSIGNED`, `BUDGET_ASSIGNED`) can also be switched per tenant by that tenant's admin. Recipients are the users holding the selected roles, so they need a valid email address.

## Step 4: Test

| Test | Do this | Expect |
|---|---|---|
| Notification | Assign a tier to a tenant, or top up its budget (`/institution-management`) | `TIER_ASSIGNED` / `BUDGET_UPDATED` email; a line in the `notifications_consumer` log |
| PPU threshold | Spend past a budget band (see `PPU-LOCAL-SETUP.md`) | `BUDGET_THRESHOLD` email |

**Something sent but no email?** Check the `notifications_consumer` log, then the failure log:

```bash
docker exec ai4v-postgres psql -U postgres -d ai4iplatform_core -c \
  "select created_at, notification_name, stage, error_code, error_message from notification_alert_failure_log order by created_at desc limit 5;"
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| `redis.exceptions.AuthenticationError: HELLO must be called…` | `REDIS_PASSWORD` is blank in the consumer's `.env` (Step 1.2). Then open a new terminal and start again. |
| `Switch: command not found` when starting | A value with spaces isn't quoted (Step 1.2) |
| Consumer logs `[ConsoleEmailProvider] would send email` | `EMAIL_PROVIDER=console` or `SMTP_HOST` blank (Step 1) |
| Consumer exits with `Fatal Kafka error — exiting for restart \| code=_AUTO_OFFSET_RESET` | Offsets were never seeded. Run Step 2.2, then start it again. |
| Nothing happens at all | The recipient roles are still off (Step 3) |
| PPU emails never arrive | `PII_ENCRYPTION_KEY` in `payperuse_consumer`'s `.env` must equal auth-service's, or recipients can't be resolved |
| `554 Email address is not verified` | SES sandbox: verify the sender and recipient |
| Error-rate / latency alerts never fire | Locally, Prometheus can only scrape **inference-service** (see `prometheus.yml`), so other services have no metrics |

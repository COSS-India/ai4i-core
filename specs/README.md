# Public API Specs (OpenAPI)

The platform's public API surface is published as a single **OpenAPI 3.1.0**
document at [`specs/openapi.json`](./openapi.json). This file is the
canonical, source-of-truth spec — point clients, SDK generators, Swagger UI
instances, and contract tests at it.

- **Format:** OpenAPI **3.1.0** (matches the `"openapi"` field at the top of
  `openapi.json`).
- **Scope:** every public API the platform serves (auth, inference, telemetry,
  alert management, PII management, OAuth, tenants, model management, …),
  aggregated from each service's runtime FastAPI router.
- **Versioning:** the `info.version` field in `openapi.json` reflects the
  current platform release tag (see `git tag -l 'v*'`).

## Per-service runtime specs

Each FastAPI service also exposes its own OpenAPI document at runtime, served
by the service itself (no separate aggregator process needed):

| Service | Runtime spec | Swagger UI |
|---|---|---|
| `auth-service` (`:8081`) | `GET /openapi.json` | `GET /docs` |
| `platform-core-service` (`:8095`) | `GET /openapi.json` | `GET /docs` |
| `inference-service` (`:8090`) | `GET /openapi.json` | `GET /docs` |

Behind the API gateway these are reachable at the same paths, scoped to the
service's route prefix.

## Updating the canonical spec

`specs/openapi.json` is regenerated by running each FastAPI app and dumping
its `app.openapi()` output, then merging. There is no separate "docs
aggregator" service — earlier drafts referenced a `services/docs-manager/`
component that was never shipped, and the per-service YAML registry it
implied does not exist in the repo. Disregard any documentation that still
points there.

To refresh the merged spec after API changes:

1. Pull the latest from each service's `/openapi.json` while it's running
   locally.
2. Merge paths and components into a single document.
3. Commit the updated `specs/openapi.json` together with the API change.

A small helper script may be added under `scripts/` in a future change; until
then this step is manual.
